# badcase-diagnosis

## 使用场景

当 AI 产品出现一个具体失败案例时，使用这个 skill。

它的目标不是简单说“模型不行”或“prompt 要优化”，而是把坏案例拆成可讨论、可定位、可修复、可复测的问题。

适合分析：

- AI 回答事实错误、逻辑跳跃、幻觉。
- AI 理解错用户意图。
- AI 输出太泛、太空、没有行动价值。
- AI 给出过度绝对、高风险或不负责任的建议。
- AI 人设漂移，角色不像、语气不像、观点不稳。
- 多轮流程中某一步质量差，影响后续结果。
- 汇总结果没有洞察，只是复述前文。
- 输出格式不稳定，导致前端、工作流或 AI Coding 下游无法使用。
- 用户觉得“不可信、不可控、不可恢复”。

## 输入材料

尽量提供以下材料。材料不完整时，也可以先做初步诊断，但必须标注“证据不足”的地方。

- 产品或功能背景。
- 用户原始输入。
- AI 实际输出。
- 期望输出或参考答案。
- 用户当时的场景和目标。
- 失败发生在第几步。
- 失败造成的影响。
- 相关 prompt、PRD、流程规则或评测标准。
- 是否有同类失败案例。
- 你初步怀疑的问题。

## 工作流程

### Step 1: 复述坏案例

先用一句话复述：

> 用户想要什么，AI 做了什么，为什么这构成失败。

不要急着归因，先确认失败现象。

### Step 2: 判断失败层级

从以下层级中选择一个或多个：

- **输入层**：用户输入太短、太模糊、上下文缺失。
- **意图理解层**：AI 没识别用户真正目标、约束或风险。
- **知识与事实层**：事实错误、引用错误、时效错误、无依据推断。
- **推理与判断层**：逻辑链断裂、结论跳跃、没有权衡。
- **角色与风格层**：人设漂移、风格不像、观点不符合角色认知框架。
- **输出结构层**：格式不稳定、字段缺失、不能被前端或下游使用。
- **体验流程层**：缺少追问、确认、重试、纠错或恢复机制。
- **安全边界层**：高风险建议过于绝对，缺少保守策略和责任边界。
- **评测标准层**：没有清楚定义“好输出”，导致只能凭感觉判断。

### Step 3: 区分根因类型

不要把所有问题归因给模型。必须区分：

- 模型能力问题。
- prompt 约束问题。
- 产品规则问题。
- 用户输入引导问题。
- 交互流程问题。
- 数据或上下文问题。
- 评测标准问题。
- 技术实现问题。

### Step 4: 判断严重程度

按以下标准分级：

- **P0**：可能造成现实伤害、金钱损失、心理伤害、法律/医疗/投资误导，或破坏核心信任。
- **P1**：影响核心体验，用户可能放弃使用或不再相信产品。
- **P2**：影响体验质量，但可通过重试、追问或人工判断缓解。
- **P3**：表达、格式、细节问题，不影响核心任务完成。

### Step 5: 给出修复方案

每个坏案例都要输出四类修复：

- **短期止血**：今天就能改的规则、提示、兜底或交互。
- **产品规则**：应该写进 PRD/SDD 的长期规则。
- **Prompt 修改**：可直接复制给 AI Coding 或 prompt 文件的补充文本。
- **回归测试**：把这个坏案例沉淀成以后每次改模型/prompt 都要复测的问题。

### Step 6: 判断是否需要进入黄金测试集

如果坏案例满足以下任一条件，建议加入 golden set：

- 影响核心体验承诺。
- 发生在高频用户场景。
- 涉及高风险建议。
- 暴露稳定的角色/风格/判断问题。
- 修改 prompt 后容易复发。

## 质量标准

好的输出应该：

- 先描述坏案例，再归因。
- 不把所有失败都归因于“模型不好”。
- 能区分模型、prompt、产品规则、交互流程和评测标准。
- 能判断严重程度，而不是所有问题一视同仁。
- 能给出今天就能改的短期方案。
- 能把坏案例沉淀成产品规则和回归测试。
- 能输出可复制到 PRD、prompt 或 AI Coding 任务里的文本。

差的输出通常表现为：

- 只说“优化 prompt”。
- 只给原则，不给具体改法。
- 没有指出证据不足。
- 没有复测方法。
- 把表达风格问题和高风险安全问题混在一起。

## 示例：名人智囊团高风险建议

坏案例：

> 用户问“我要不要辞职创业”，某个名人角色直接给出“你应该立刻辞职”的绝对建议，没有追问现金流、家庭责任、备选方案和风险承受能力。

诊断：

- 严重程度：P0 / P1 之间，取决于用户是否可能直接采纳。
- 失败类型：安全边界层 + 意图理解层 + 产品规则层。
- 主要根因：prompt 只强调“直接给观点”，但没有定义高风险决策的保守输出规则。
- 短期止血：遇到辞职、投资、法律、医疗、心理等问题时，禁止给单一路径绝对建议。
- 产品规则：必须输出“可验证的小步行动”，而不是替用户做决定。
- 回归测试：把“我要不要辞职创业”加入黄金测试集，每次改 prompt 后复测。

## 不适用场景

不适合用来：

- 替代法律、医疗、心理、投资等专业审查。
- 处理完全没有具体输入输出的笼统抱怨。
- 直接评估底层模型能力排行榜。
- 诊断复杂 RAG 检索链路的召回、切片、重排问题。
- 替代线上监控、日志追踪和自动化 eval 系统。

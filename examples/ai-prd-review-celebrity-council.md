## 0. 这个案例展示了什么

这个案例展示 `ai-prd-reviewer` 的 5 个核心能力：

1. **不只是检查 PRD 格式**：它会判断 PRD 是否真的能支撑一个 AI 产品体验。
2. **能识别 AI 产品特有缺口**：比如模型行为边界、输出质量标准、bad case、golden set 和失败兜底。
3. **能区分功能完成和体验成熟**：名人智囊团已经完成 MVP，但还需要补齐“什么叫好回答、好辩论、好汇总”的验收标准。
4. **能给出可直接补进 PRD 的文本**：不是只说“需要优化”，而是输出可以粘贴到 PRD 里的规则、验收标准和 prompt 方向。
5. **能判断 AI Coding 交接成熟度**：哪些 backlog 可以直接交给 Codex/Claude Code，哪些还要先被产品经理拆清楚。

## 1. PRD 类型与评审重点

- PRD 类型：迭代型 PRD + 多角色型 AI PRD + AI Coding 交接型 PRD。
- 当前成熟度：可开发，已完成 MVP；但还未达到“可稳定验收 AI 输出质量”的程度。
- 本次最重要的评审重点：AI 输出质量标准、汇总质量标准、异常兜底、AI Coding 任务交接。
- 不建议当前深入的部分：底层模型 benchmark、RAG、复杂后端架构。

## 2. 总体结论

- 完整度评分：78 / 100
- 开发交接风险：中
- 一句话判断：名人智囊团的现有 PRD/SDD 已经能指导功能开发，但还不足以指导“高质量 AI 体验”的稳定验收。

详细判断：

1. 这份 PRD 当前最清楚的地方：核心流程、页面结构、API 调用、技术选型、名人库来源、时间线体验和开发阶段记录都很完整。对一个已完成 MVP 的小程序来说，它已经具备很好的项目记忆和工程交接价值。

2. 这份 PRD 当前最大的缺口：它把“功能怎么跑通”写得很清楚，但没有把“什么叫好回答、好辩论、好汇总、好行动计划”定义清楚。对这个产品来说，AI 输出质量就是核心功能质量，如果没有验收标准，后续很难判断迭代是否真的变好。

3. 如果只补 3 件事，应该先补：第一，补 AI 输出质量标准；第二，补高风险问题的模型行为边界；第三，把 backlog 改成可执行的 AI Coding 任务。

## 4. 优先缺口详拆

### 缺口 1：缺少 AI 输出质量标准

- 类型：AI 行为 / 评测
- 优先级：P0
- 当前表现：PRD 对回答格式、字数、语气有要求，但没有定义“什么叫有洞察”“什么叫名人观点有效”“什么叫辩论产生信息增量”。
- 为什么会影响落地：开发和 prompt 可以让功能跑通，但无法判断回答质量是否达到产品目标。后续每次改 prompt 都可能只是风格变化，不一定提升体验。
- 建议补充：给“名人回答、辩论、主持人汇总、行动计划”分别定义验收标准。
- 负责人：产品 + prompt + 测试
- 验收标准：抽样 10 个典型问题，至少 7 个回答能提供隐藏假设、关键变量、判断框架、现实约束或小步实验之一。

### 缺口 2：模型行为边界不够完整

- 类型：AI 行为 / 风险
- 优先级：P0
- 当前表现：`docs/API.md` 和 `docs/DECISIONS.md` 有“不要说免责声明”的旧约束；现有文档没有区分普通问题和高风险问题。
- 为什么会影响落地：产品定位是“人生/职业/创业/决策困境”，很容易涉及辞职、投资、心理、法律、关系等高风险问题。没有边界会导致 AI 输出过度确定的建议。
- 建议补充：改成“不要机械免责声明，但必须表达模拟边界和不可替用户决策边界”。
- 负责人：产品 + prompt
- 验收标准：输入“我要不要辞职/投资/分手/起诉/我是不是抑郁了”等问题时，汇总和行动计划不得直接给不可逆指令，必须先给低风险验证步骤。

### 缺口 3：汇总和行动计划没有稳定结构

- 类型：体验 / AI 行为 / 交接
- 优先级：P0
- 当前表现：`callSummary` 要求总结“分歧、共识、一句建议”；`callActionPlan` 要求 3-5 个步骤，但没有定义真正问题、现实约束、下一步验证。
- 为什么会影响落地：汇总和行动计划是体验收口，如果它们只是普通总结，前面的多角色和辩论价值会被削弱。
- 建议补充：主持人汇总改为固定四段式，行动计划要求低风险、可验证、可撤回。
- 负责人：产品 + prompt + 开发
- 验收标准：汇总结果必须包含“真正的问题、关键分歧、现实约束、下一步验证”；行动计划第一步必须是低风险动作。

### 缺口 4：缺少 bad case 与回归测试机制

- 类型：评测
- 优先级：P0
- 当前表现：项目中有黄金评测集文件，但主 PRD/SDD 没有把它纳入开发流程，也没有定义评分标准。
- 为什么会影响落地：AI 产品迭代不能只看主观感觉，需要每次改 prompt 后用同一批问题回归测试。
- 建议补充：建立 10-20 条 golden set，覆盖职业、创业、人生、学习、投资、情绪、高风险问题。
- 负责人：产品 + 测试
- 验收标准：每次 prompt 变更后记录评测结果，至少包含洞察度、贴合度、可执行性、风险边界四项评分。

### 缺口 5：Backlog 还不是 AI Coding 可执行任务

- 类型：交接
- 优先级：P1
- 当前表现：Backlog 写了微信云开发数据同步、小程序码、分享携参，但没有任务拆解、涉及文件、验收标准。
- 为什么会影响落地：如果直接交给 Codex/Claude Code，实现时还要重新澄清范围。
- 建议补充：把每个 backlog 拆成任务目标、涉及文件、实现范围、验收标准、不要改什么。
- 负责人：产品 + 开发
- 验收标准：AI Coding 工具拿到任务后不需要再追问实现范围，就能开始改代码。

## 5. 可直接补进 PRD 的内容

### 产品目标补充

```markdown
名人智囊团的核心目标不是生成多个名人口吻回答，而是通过多种认知模型的碰撞，帮助用户获得更深刻、更现实、可行动的判断。

一次高质量体验应满足：
- 用户的问题被重新理解或重构；
- 至少一位名人指出用户忽略的关键变量；
- 辩论产生新的信息增量，而不是重复表达；
- 主持人汇总能提炼真正分歧、现实约束和下一步验证；
- 行动计划以低风险、可执行、可撤回的小步骤为主。
```

### 用户流程补充

```markdown
在用户输入问题前，产品应提供结构化提问引导，帮助用户补充背景、纠结点、目标和限制。

推荐模板：
- 职业选择：我现在的背景是___，纠结点是___，限制是___，我想判断___。
- 创业/产品：我想做___，目标用户是___，目前卡在___，我担心___。
- 人生困惑：我现在处在___状态，已经尝试过___，我希望得到___。
```

### AI 行为规则补充

```markdown
名人回答必须提供真实信息增量，不得只模仿名人口吻。每条回答至少应完成以下一种任务：
- 指出用户问题里的隐藏假设；
- 找出一个被忽略的关键变量；
- 给出一个判断框架；
- 提醒一个现实约束或代价；
- 提出一个低风险的小步实验。

辩论回复必须指出其他观点遗漏的变量、适用边界、现实代价或反例，不得只制造语气冲突。

主持人汇总必须包含：
1. 真正的问题：用户表面在问什么，实际需要判断什么；
2. 关键分歧：各方观点背后的不同假设；
3. 现实约束：用户做决定前必须确认的条件；
4. 下一步验证：一个低风险、明天能做的小行动。
```

### 异常与兜底补充

```markdown
当用户问题涉及职业重大决策、投资金钱、心理健康、法律纠纷、医疗健康、人身安全或亲密关系重大决定时，系统不得输出绝对化、诊断式或不可逆建议。

高风险问题下，行动计划必须优先建议：
- 收集信息；
- 沟通验证；
- 小范围试验；
- 咨询可信赖的人或专业人士。

系统不使用大段机械免责声明，但必须清楚表达：AI 输出是模拟观点和启发式建议，不代表名人本人观点，也不替用户做最终决定。
```

### 验收标准补充

```markdown
AI 输出质量验收：
- 洞察度：是否指出隐藏假设、关键变量或判断框架；
- 贴合度：是否回应用户真实问题，而不是泛泛建议；
- 差异度：三位名人是否提供不同认知模型；
- 辩论增量：辩论是否产生新变量、新边界或新取舍；
- 汇总质量：是否提炼真正问题、关键分歧、现实约束和下一步验证；
- 可执行性：行动计划是否低风险、具体、明天可做；
- 风险边界：高风险问题是否避免不可逆建议。

评分建议：每项 1-5 分，低于 3 分的输出进入 bad case 复盘。
```

## 6. AI Coding 交接建议

- 可以直接交给 AI Coding 的部分：
  - 首页增加结构化提问模板。
  - 行动计划 prompt 增加低风险验证规则。
  - 主持人汇总 prompt 改成四段式。
  - 回答卡片增加“重写这位”入口。

- 还不能直接交给 AI Coding 的部分：
  - “提升回答深度”这种目标需要先转成可验收 prompt 规则。
  - “更有名人味”需要样例和 bad case 支撑。
  - “更安全”需要先定义高风险问题范围。

- 需要先确认的问题：
  - 产品更偏“好玩犀利”还是“现实有用”？
  - 是否保留“不要说免责声明”的旧规则，还是改为“不要机械免责声明，但表达边界”？
  - 是否愿意牺牲一点输出戏剧性，换取高风险问题的稳健性？

- 建议拆成的开发任务：
  1. 修改 prompt：回答增加洞察质量标准。
  2. 修改 prompt：辩论增加信息增量标准。
  3. 修改 prompt：汇总改为四段式。
  4. 修改 prompt：行动计划增加低风险验证规则。
  5. 首页增加 3 个提问模板 chip。
  6. 时间线回答卡片增加“重写这位”。
  7. 建立 10 条 golden set 评测记录。

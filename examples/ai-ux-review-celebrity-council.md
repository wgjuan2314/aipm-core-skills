评审日期：2026-05-26

使用 skill：`skills/ai-ux-review/SKILL.md`

## 1. 产品类型与评估重点

- 产品类型：多角色/多智能体型 AI 决策辅助产品。
- 核心体验承诺：用户带着一个真实困惑进入，系统匹配 3 位合适的名人，用不同认知模型独立回答、相互辩论，最后由主持人汇总成一个更深刻、更现实、可行动的判断。
- 本次评估最重要的 3 个维度：输出质量、过程体验、汇总与落地。
- 不应过度关注的维度：普通 UI 审美和单纯风险提示。风险边界重要，但不是这个产品的核心体验本身。

## 2. 总体结论

- 体验成立度：中偏强
- 风险等级：中
- 一句话判断：名人智囊团的产品概念和主流程已经成立，真正要继续打磨的是“洞察密度、观点碰撞、汇总质量、行动计划现实性”，而不是只补一句免责声明。

详细判断：

1. 这个 AI 体验最有价值的地方：它把“向 AI 提问”改造成了一个有仪式感的思考过程。用户不是直接拿到一个答案，而是先看到系统组建智囊团，再看到不同名人的独立观点、辩论、追问、汇总和行动计划。这个流程让用户感觉自己不是在问一个机器人，而是在组织一次思想会议。

2. 当前最影响核心体验的问题：产品已经有“多角色”，但还需要证明每个角色真的贡献了不同认知模型，而不是三个有名人语气的回答。尤其最终汇总必须比单个名人回答更高级，否则“智囊团”会退化成“回答列表 + 总结器”。

3. 如果只改 3 件事，应该先改：第一，增强输入引导，让用户提出更有上下文的问题；第二，增强汇总质量，让主持人提炼真正的分歧、共识和现实下一步；第三，增强高风险问题下的行动计划边界，让建议更像小步验证，而不是替用户做决定。

## 4. 核心体验详拆

### 核心体验 1：用户是否真的获得了更深刻的判断

- 用户场景：用户问“我要不要辞职”“我现在做独立产品还有机会吗”“要不要继续创业”这类复杂问题。
- 当前表现：系统会给 3 位名人回答，再辩论，再汇总。
- 为什么重要：这个产品的卖点不是陪聊，而是让用户从单一视角跳出来，看到更高质量的判断框架。
- 体验是否成立：部分成立。流程成立，但还缺少对输出洞察质量的硬要求。
- 证据：名人回答 prompt 要求“有活人感、幽默、犀利、禁止 AI 腔”，但没有要求“指出用户问题背后的错误前提、关键变量、现实约束”。
- 建议改法：给名人回答 prompt 加入“洞察质量标准”，要求每次回答至少完成一种价值：重构问题、指出盲点、给出判断框架、提供现实约束、提出小步实验。
- 验收标准：用 10 个复杂问题测试，至少 7 个回答能指出用户问题背后的一个隐藏假设或关键变量。

### 核心体验 2：多角色是否真的产生观点碰撞

- 用户场景：用户点击“相互辩论”或“再辩一轮”。
- 当前表现：每位名人会“挑一个最看不惯的点反驳”。
- 为什么重要：“智囊团”的差异化来自观点冲突。如果只是三个角色轮流表态，体验会变薄。
- 体验是否成立：中偏强。产品有辩论机制，但需要防止反驳变成口吻上的热闹。
- 证据：`callDebateRound` 强调“挑一个最看不惯的点反驳”，但没有要求反驳必须带来新信息。
- 建议改法：辩论 prompt 增加“不要只反驳语气，要指出对方观点遗漏的变量、适用边界或现实代价”。
- 验收标准：每轮辩论至少出现 1 个新变量，例如现金流、机会成本、时间窗口、心理能量、资源约束、风险暴露。

### 核心体验 3：最终汇总是否比单个回答更高级

- 用户场景：用户看完多轮辩论后点击“智囊汇总”，希望得到一个可保存、可行动的结论。
- 当前表现：主持人 prompt 要求输出“分歧、共识、一句建议”，150 字以内。
- 为什么重要：汇总是整个体验的收口。如果汇总不够深，前面的多角色和辩论都会打折。
- 体验是否成立：部分成立。结构是对的，但 prompt 太轻，容易变成普通总结。
- 证据：`callSummary` 没要求识别“真正问题”“关键取舍”“下一步验证方式”。
- 建议改法：主持人汇总改成 4 段：真正的问题、各方分歧、现实约束、下一步小实验。
- 验收标准：汇总里必须出现一个“你真正要判断的不是 X，而是 Y”式的重构，或一个可验证的现实下一步。

## 5. 优先问题详拆

### 问题 1：输入引导不足，导致用户问题质量不稳定

- 优先级：P0
- 用户场景：用户打开首页，只看到“请写下你的问题”，随手输入“我该不该辞职”。
- 触发条件：用户问题缺少背景、目标、约束、已尝试方案。
- 当前表现：首页有弹幕示例，但输入区没有引导用户补充关键信息。
- 为什么这是问题：AI 输出质量高度依赖输入质量。复杂问题如果没有上下文，名人回答容易变成泛泛建议。
- 可能造成的后果：用户觉得回答有风格但不够贴身，降低复用意愿。
- 建议改法：输入区增加“问题质量引导”，用轻量 chip 或 placeholder 引导用户补充“背景/纠结点/目标/限制”。
- 负责人：产品 + 设计 + 开发
- 验收标准：用户输入前能看到至少 3 个可点选的提问模板；模板能自动填入结构化问题骨架。

### 问题 2：名人回答偏风格约束，缺少洞察质量约束

- 优先级：P0
- 用户场景：用户看第一轮 3 位名人回答。
- 触发条件：名人 system prompt + 附加风格要求生成回答。
- 当前表现：prompt 强调有活人感、幽默、犀利、禁止 AI 腔。
- 为什么这是问题：风格能提升可读性，但不等于洞察。AI 可能输出很像名人、很有金句，但没有现实判断价值。
- 可能造成的后果：用户初看觉得爽，复盘后发现没有真正可用的东西。
- 建议改法：给回答 prompt 增加“洞察必须落地”的规则：指出一个隐藏假设、一个关键变量、一个现实约束，或一个小步实验。
- 负责人：prompt
- 验收标准：抽样 10 条回答，至少 7 条包含明确的“关键变量/隐藏假设/小步实验”。

### 问题 3：主持人汇总不够重，承载不了最终体验价值

- 优先级：P0
- 用户场景：用户看完辩论后，希望主持人给出综合判断。
- 触发条件：用户点击“智囊汇总”。
- 当前表现：主持人只被要求总结核心分歧、共识和一句建议。
- 为什么这是问题：汇总应该是整个体验的认知收口，而不是复述前文。
- 可能造成的后果：用户不会想保存或分享汇总，产品记忆点变弱。
- 建议改法：主持人汇总 prompt 要求输出“真正问题、关键分歧、现实约束、下一步验证”。
- 负责人：prompt + 产品
- 验收标准：汇总结果能独立阅读，即使不看前文也能理解用户该如何继续思考。

### 问题 4：行动计划现实性不足，可能从启发变成命令

- 优先级：P0
- 用户场景：系统自动生成行动计划。
- 触发条件：主持人汇总完成后调用 `callActionPlan`。
- 当前表现：prompt 要求 3-5 个具体步骤，明天可以开始，按优先级排列。
- 为什么这是问题：这个方向是对的，但还没有要求步骤低风险、可验证、可撤回。
- 可能造成的后果：用户面对高风险问题时，可能得到过于确定的行动建议。
- 建议改法：行动计划 prompt 增加“小步验证、低风险优先、不可逆动作延后、专业事项先咨询”的规则。
- 负责人：prompt + 开发
- 验收标准：对于“辞职/投资/分手/法律/心理”等问题，行动计划第一步必须是收集信息、沟通验证或咨询，而不是直接行动。

### 问题 5：缺少局部纠错，无法让用户修正坏输出

- 优先级：P1
- 用户场景：三位名人中有一位回答跑题、太空、太激进。
- 触发条件：局部输出失败。
- 当前表现：用户可以追问、换题，但不能只重写一位名人的回答。
- 为什么这是问题：AI 产品常见失败是局部失败，不应该让用户为一条坏输出重跑完整流程。
- 可能造成的后果：用户中断探索，或者认为产品不稳定。
- 建议改法：回答卡片增加“重写这位”“太空了”“太激进”入口。第一版先做“重写这位”。
- 负责人：设计 + 开发
- 验收标准：用户能对单条回答重新生成，原问题、阵容和其他回答保持不变。

## 7. 可直接加入 PRD 的补充文本

```markdown
### AI 体验质量标准

名人智囊团的核心价值不是生成多个名人口吻的回答，而是通过多种认知模型的碰撞，帮助用户获得更深刻、更现实、可行动的判断。

一条合格的名人回答至少应提供一种信息增量：指出隐藏假设、识别关键变量、给出判断框架、提醒现实约束，或提出低风险小实验。回答不能只模仿名人口吻，也不能只输出鸡汤式金句。

一轮合格的辩论必须产生新的认知增量。反驳应指出对方观点遗漏的变量、适用边界、现实代价或反例，而不是只制造语气冲突。

主持人汇总是产品体验的核心收口，必须包含：真正的问题、关键分歧、现实约束、下一步验证。汇总应帮助用户继续思考和行动，而不是简单复述各方观点。

行动计划应优先小步验证，不替用户做不可逆决定。涉及职业、投资、法律、医疗、心理健康、人身安全或亲密关系重大决定时，系统应优先建议收集信息、沟通验证或咨询专业人士。
```

- 是否有 5-10 条你认为“问得好”的真实用户问题。
- 是否有你理想中的一条“高质量汇总”样例。
- 当前名人回答是否已经做过人工筛选或用户反馈。

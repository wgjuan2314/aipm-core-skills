# Agent Fit Analysis: 名人智囊团

> 这是 `agent-fit-analyzer` 的真实项目分析案例。
>
> 被分析项目“名人智囊团”是项目 owner 真实开发过的 AI 微信小程序：用户输入一个决策困惑，系统自动匹配 3 位名人角色，生成独立回答、辩论、追问、主持人汇总和行动计划。
>
> 这个案例的目的不是判断项目“高级不高级”，而是展示 `agent-fit-analyzer` 如何帮助 AI 产品经理判断：这个需求到底应该做普通 AI 功能、Copilot、确定性工作流、局部 agentic step，还是 Full Agent。

## 0. 这个案例展示了什么

这个案例展示 `agent-fit-analyzer` 的 5 个核心能力：

1. **先看产品目标，再判断 Agent 必要性**：不会一上来套 Agent 概念，而是先判断用户真正需要的是启发、判断还是自动执行。
2. **避免过度 Agent 化**：不会因为产品里有多轮 AI 调用、多角色和行动计划，就直接判断它适合做 Full Agent。
3. **区分 workflow、Copilot 和 Agent**：名人智囊团更像确定性 AI 工作流 + 多角色决策 Copilot，而不是自主执行 Agent。
4. **识别局部 agentic step**：系统可以在“选人、汇总策略、问题类型识别”等节点使用动态判断，但不需要全流程自主规划。
5. **输出更专业的产品形态命名**：帮助 AI PM 把“要不要做 Agent”转成可讲清楚的产品架构选择。

## 1. 结论

- 推荐形态：确定性 AI 工作流 + 多角色决策 Copilot + 局部 agentic step。
- Agent 适配度：中。
- 自主执行风险：中高。
- 一句话判断：名人智囊团不适合做 Full Agent，它的核心价值是多角色认知碰撞和决策启发，而不是替用户跨系统执行任务。

## 2. 任务画像

- 产品核心目标：帮助用户通过多种认知模型重构问题、获得启发和下一步判断。
- 用户目标：获得多个认知视角，帮助自己思考职业、创业、人生或决策困惑。
- AI 应承担的角色：组织观点、生成启发、提炼分歧和建议，而不是替用户执行现实动作。
- 任务步骤是否固定：基本固定。当前流程是输入问题 → AI 选人 → 阵容确认 → 独立回答 → 辩论 → 追问 → 主持人汇总 → 行动计划。
- 是否需要动态决策：部分需要。主要体现在 AI 选人、根据问题类型调整汇总策略、高风险问题兜底。
- 是否需要工具调用：当前不需要外部工具调用，只需要调用模型。
- 是否会执行真实动作：当前不会。行动计划只是建议，不会自动发消息、下单、投资、报名、辞职或修改外部系统。
- 失败是否可恢复：部分可恢复。用户可以换人、追问、换题，但不能单条重写或纠正 AI 理解。

## 3. Agent 适配度评分

| 维度 | 判断 | 证据 | 分数 |
| --- | --- | --- | --- |
| 目标清晰度 | 高 | 用户目标是获得多元视角和思维启发。 | 4 |
| 步骤不确定性 | 低 | 核心流程基本固定。 | 2 |
| 动态决策需求 | 中 | 需要 AI 选择 3 位名人，也可以根据问题类型调整汇总。 | 3 |
| 工具调用需求 | 低 | 当前只调用 DeepSeek，不跨工具执行。 | 1 |
| 自主执行价值 | 低 | 产品价值来自启发用户，而不是替用户执行任务。 | 2 |
| 失败成本可控 | 中 | 输出建议可能影响重大决策，但当前不直接执行动作。 | 3 |
| 可观测与可恢复 | 中 | 有时间线和历史记录，但缺少单条重写、反馈和回滚机制。 | 3 |

综合判断：不适合 Full Agent，适合在固定工作流中加入少量 agentic step。

## 4. 为什么适合 / 不适合 Agent

### 适合的理由

- 有一个明确目标：帮助用户获得更好的决策视角。
- 部分环节需要动态判断：AI 选人、问题类型识别、汇总策略选择。
- 多角色协作让它具备一定 agentic 味道。

### 不适合的理由

- 主流程已经是稳定工作流，不需要 Agent 自主规划步骤。
- 当前没有跨系统工具调用，也没有真实执行动作。
- 用户需要的是启发和判断框架，不是自动执行。
- 如果升级成 Full Agent，反而会增加不必要的风险和复杂度。

### 最大风险

如果把它做成 Full Agent，例如让它自动替用户执行行动计划，风险会明显升高。用户可能问“我要不要辞职/投资/分手”，Agent 如果继续执行“发消息、提交申请、转账、报名”等动作，就会越过产品边界。

## 5. 更合适的产品形态

- 推荐方案：多角色决策 Copilot。
- 为什么它比 Full Agent 更适合：用户需要的是认知启发和判断框架，而不是系统替他完成现实世界任务。Full Agent 会引入工具权限、误操作和责任边界问题，反而削弱产品可信度。
- 用户体验形态：用户提出问题，系统组织智囊团讨论，输出观点、分歧、汇总和小步行动建议；最终选择权始终在用户手里。
- AI 扮演的角色：
  - Router：选择合适名人。
  - Role Players：提供不同认知框架。
  - Debaters：指出观点冲突和遗漏变量。
  - Moderator：综合观点并给出下一步验证。
- 局部 agentic step：
  - AI Router：根据问题动态选择最合适的 3 位名人。
  - Debate Orchestrator：组织观点碰撞，决定如何推进辩论。
  - Moderator：提炼真正分歧、共识和下一步验证。
  - Risk Classifier：识别辞职、投资、法律、心理等高风险问题，并切换成更保守的建议策略。
- 人类确认点：
  - 用户确认阵容。
  - 用户决定是否继续辩论。
  - 用户决定是否追问。
  - 用户决定是否采纳行动计划。
- 最小可行版本：
  - 保持当前固定流程。
  - 只在选人、汇总策略、高风险问题识别上加入 agentic step。
  - 不做自动执行。

## 6. 如果坚持做 Agent，需要满足的条件

| 条件 | 为什么需要 | 最小实现 |
| --- | --- | --- |
| 明确可执行任务边界 | 防止 Agent 自动执行高风险动作 | 只能生成建议，不允许外部写入 |
| 人工确认点 | 用户必须保留最终决定权 | 所有行动计划只作为 checkbox，不自动执行 |
| 高风险问题识别 | 职业、投资、心理、法律等场景不能自动化推进 | 本地关键词 + prompt 保守策略 |
| 日志和回放 | 方便用户理解 AI 如何得出建议 | 保存问题、名人回答、辩论、汇总 |
| 单步恢复 | 局部失败时不重跑全流程 | 增加“重写这位” |

## 7. 可直接加入 PRD 的补充文本

```markdown
### Agent 形态边界

名人智囊团不设计为 Full Agent。产品不替用户跨系统执行真实动作，也不自动替用户做职业、投资、法律、医疗、心理或亲密关系等重大决策。

产品形态定义为“多角色决策 Copilot + 确定性 AI 工作流 + 局部 agentic step”。系统按照固定流程组织多位名人角色进行回答、辩论和汇总，仅在以下节点使用 agentic step：

- 根据用户问题动态选择 3 位名人；
- 根据问题类型调整汇总策略；
- 根据辩论内容提炼真正分歧和遗漏变量；
- 对高风险问题使用更保守的行动建议；
- 在后续版本中支持对单条回答进行重写或纠错。

所有行动计划均为启发式建议，由用户自行确认、执行或忽略。系统不得自动发送消息、提交申请、转账、报名、发布内容或执行任何外部写入动作。
```

## 8. AI Coding 交接建议

- 可以直接实现的部分：
  - 保持当前固定流程，不改为自由规划 Agent。
  - 增加高风险问题识别。
  - 增加“重写这位”局部恢复。
  - 在 PRD 和 prompt 中明确“不自动执行真实动作”。

- 还需要产品确认的部分：
  - 是否要把“行动计划”升级成可跟踪 checklist。
  - 是否允许未来接入日历、待办、微信消息等外部工具。
  - 如果接入工具，哪些动作需要二次确认。

- 不建议自动执行的部分：
  - 自动帮用户辞职、发消息、转账、下单、报名、发布内容。
  - 自动替用户做法律、医疗、投资、心理健康相关决定。
  - 自动修改外部系统数据。
